# Logging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A finished `/api` action stores an `EnrichedRequest` and writes `http.request.start` and `http.request.finish` on the `application` channel, while Symfony's lines stay in their own file.

**Architecture:** `UuidRequestIdFactory` keeps a valid `X-Request-Id` or mints a UUID version 4 with `random_bytes`. `RequestEnricher` reads the first id and the User-Agent and Referer into `EnrichedRequest`. `LogApiRequest` runs on `kernel.controller` and `kernel.response` for `Yumo\Eleanor\Controller\Api`, stores that object on the request, and writes the two `info` lines. Monolog's `eleanor` handler is a top-level JSON handler for `application` and `domain`. Symfony's handlers keep the 3.7 recipe and exclude those two channels.

**Tech Stack:** PHP 8.5, Symfony 8.1, `symfony/monolog-bundle` `4.0.*` (Flex applies the 3.7 recipe; bundle 3.11 does not allow Symfony 8), Monolog 3, existing PHPUnit 11, `./bin/composer`, `./bin/test`, `./bin/quality`.

**Spec:** `packages/web-app/doc/features/0002-server/specs/Logging.md`

## Global Constraints

- Where `logging.md` and the spec disagree, the spec wins. The two lines are `http.request.start` and `http.request.finish`, both level `info` on channel `application`. There is no `http.request` line.
- `RequestIdFactory::fromHeader(?string $value): string` keeps `$value` when it is 1 to 128 characters and every character is an ASCII letter (`A-Z`, `a-z`), an ASCII digit, `.`, `_`, or `-`. `null`, `''`, and any other value return a new UUID version 4 built with `random_bytes`. Do not install `symfony/uid` or any other package for this.
- `UuidRequestIdFactory` is the implementation. `RequestEnricher` depends on the interface. `LogApiRequest` depends on `RequestEnricher`, not on the factory. Symfony autowires the one implementation. This slice adds no configuration key and does not edit `config/services.yaml`.
- `RequestEnricher` is final. `enrich(Request $request): EnrichedRequest` passes the first `X-Request-Id` value, or `null` when the header is absent, to the factory. A second value cannot replace the first. `userAgent` and `referer` are the header values when the client sent a non-empty one. A missing header or `''` is `null`.
- `EnrichedRequest` holds `requestId`, `userAgent`, and `referer`. The attribute key is `EnrichedRequest::class`.
- On `kernel.controller`, for a main request whose controller class is in `Yumo\Eleanor\Controller\Api`, store the enriched request, store `hrtime(true)`, then write `http.request.start`. The controller on disk is still `Yumo\Eleanor\Controller\Api\CreateArchiveController`. Do not move it. The payload slice updates this namespace check.
- On `kernel.response`, when that attribute is present, set `X-Request-Id` to `requestId`, then write `http.request.finish`. `duration_ms` is the elapsed nanoseconds from the stored start until this write, divided by one million and truncated to an integer.
- A 404 and a 405 do not run `kernel.controller`. The attribute is absent. `kernel.response` does not write and does not set the header.
- Start context keys: `method`, `route` (the route name), `path`, `request_id`. `path` is the path and the query string, with no scheme and no host, and with no trailing `?` when the query is absent. `user_agent` and `referer` are included only when the enriched value is non-null.
- Finish context keys: `request_id`, `status` (integer), `duration_ms` (non-negative integer).
- The lines do not include the body, a bearer token, article HTML, upstream response headers, or an exception. `POST /api/archives` still returns 200, `{"ok":true}`, and `application/json`. The controller does not read User-Agent, Referer, or `X-Request-Id`, and does not set the response header. Do not edit `CreateArchiveController`.
- A failed log write is caught at the subscriber and not rethrown. The enriched attribute and the start time are stored before either write. The finish path sets `X-Request-Id` before the write.
- When the action throws after the start line, the subscriber writes `http.request.finish` at `info` with that response's status. Symfony's uncaught exception stays on the `app` channel. This slice adds no Eleanor exception type and no Monolog processor.
- Eleanor installs `symfony/monolog-bundle` `4.0.*`. The direct dependency is that bundle only. `monolog/monolog` and `symfony/monolog-bridge` stay transitive. The channel list keeps `deprecation` and adds `application` and `domain`.
- Files live in `%kernel.logs_dir%`. Symfony's file is `%kernel.environment%.log`. Eleanor's file is `eleanor.%kernel.environment%.log`. `dev` and `test` append with a stream. `prod` uses `rotating_file`, `max_files: 7`, and the bundle defaults `{filename}-{date}` and `Y-m-d`, so the files are `prod-YYYY-MM-DD.log` and `eleanor.prod-YYYY-MM-DD.log`. Do not set `filename_format` or `date_format`.
- The `eleanor` handler is top-level in every environment. It accepts only `application` and `domain`. Its level is `debug` in `dev` and `test`, and `info` in `prod`. Its formatter is `monolog.formatter.json` with `include_stacktraces: true`.
- Symfony's handlers keep the 3.7 recipe's levels, `fingers_crossed` placement, 404 and 405 exclusion, production buffer of 50, `event` exclusion in `dev`, `!event` on the test `main` handler, `!deprecation` on the prod `main` handler, and the console handler in `dev` and `prod`. `test` has no console handler. The production nested handler is a rotating file with the JSON formatter, not stderr. Deprecations stay on stderr, channel `deprecation`, with that JSON formatter and `include_stacktraces: true`. `dev` and `test` line formatters do not set the flag.
- Every Symfony handler that would otherwise receive `application` or `domain` excludes both. On `fingers_crossed` the exclusion sits on `main`, not on `nested`. The console handler excludes them too. The `app` channel stays on the Symfony side.
- `tests/Request/UuidRequestIdFactoryTest.php` does not boot the kernel. `tests/Integration/LogApiRequestTest.php` is a `WebTestCase` in `Yumo\Eleanor\Tests\Integration`. It reads the `EnrichedRequest` on the request the client sent. It does not open a log file, and it does not assert `X-Request-Id` on the response.
- `CreateArchiveRouteTest` and `KernelTest` stay. They do not assert the log or the attribute. Do not edit `phpunit.xml.dist`, `config/packages/framework.yaml`, or `config/routes.yaml`.
- Allowed environments stay `prod`, `dev`, and `test`. No glossary term. `domain` has no writer. No owner email, bearer token, firewall, payload refusal, or archive storage.

## Review Focus

1. A locale-aware `ctype_alnum` would keep `é`. Task 1 `test_replaces_values_outside_the_rule` case `non-ascii` sends `é` and expects a UUID version 4.
2. Trimming would turn ` a ` into `a` and keep it. Task 1 case `padded` sends ` a ` and expects a UUID version 4.
3. Taking the last `X-Request-Id`, or joining the values, would drop a valid first id. Task 3 `test_valid_first_id_wins_over_a_second_id` sends `kept-id` then `other-id` and expects `kept-id` on the attribute.

5. The test client inserts `HTTP_USER_AGENT` `Symfony BrowserKit`, and `Request::create` inserts `Symfony` when the key is absent. Task 3 `test_missing_user_agent_and_referer_are_null` omits both keys and expects `null`, which fails if either default is stored.

public function test_post_stores_the_sent_id_agent_and_referer(): void
{
    $client = static::createClient();
    $client->request('POST', '/api/archives', server: [
        'HTTP_X_REQUEST_ID' => 'kept-id',
        'HTTP_USER_AGENT' => 'ArchiveClient/1',

- [ ] **Step 3: Implement the enricher and the subscriber**

`EnrichedRequest` is a final readonly class with the constructor in Interfaces. JSDoc on the class.

`RequestEnricher::enrich` reads `headers->all('X-Request-Id')` and passes index `0` when that element is a string, otherwise `null`. It does not call `headers->get('X-Request-Id')`. User-Agent and Referer use `headers->get`. `null` and `''` become `null`. JSDoc on the class and `enrich`.

`LogApiRequest` is final, implements `EventSubscriberInterface`, and carries `#[WithMonologChannel('application')]`. Constructor: `RequestEnricher $enricher`, `LoggerInterface $application`. Subscribed events: `KernelEvents::CONTROLLER` to `onController`, `KernelEvents::RESPONSE` to `onResponse`, default priority.

`onController` returns unless `$event->isMainRequest()` and the controller object class starts with `Yumo\Eleanor\Controller\Api\`. An array controller uses index `0`. Comment why this namespace is the one on disk: the payload slice moves the controller and updates this check. Then `enrich`, store the object under `EnrichedRequest::class`, store `hrtime(true)` under the private attribute `eleanor.http_request_started_at`, then `info('http.request.start', $context)` inside `try` / `catch (\Throwable)`. The catch comment: a failed write must not change the action's response.

Start context: `method` from `getMethod()`, `route` from the `_route` attribute string, `path` from `getPathInfo()` plus `?` and `getQueryString()` when that string is non-empty, `request_id` from `requestId`. Add `user_agent` and `referer` only when non-null. No other keys.

`onResponse` returns unless the attribute is an `EnrichedRequest`. Set response header `X-Request-Id` to `requestId`. When the stored start is an int, `duration_ms` is `intdiv(hrtime(true) - $startedAt, 1_000_000)`. Then `info('http.request.finish', ...)` in the same catch. Finish context is only `request_id`, `status`, and `duration_ms`. When the stored start is not an int, skip that write. The header is already set.

Do not edit `config/services.yaml`. Autoconfigure registers the subscriber. Autowire binds `RequestIdFactory` to `UuidRequestIdFactory`.
