# Error Response Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every failure under `/api` answers `application/json` with `code` and `message`. One serializer writes success and error bodies. An OpenAPI document is generated from the code, committed, and checked by a test.

**Architecture:** The archive module raises one `ArchiveException` that carries an `ArchiveFailure` (string enum, values are wire codes). A mapper turns library failures into it. The HTTP layer has two body types (`ArchiveResponse`, `ErrorResponse`) and a generic `Reply` that pairs a status with a body. The controller returns a `Reply`. A `kernel.view` subscriber and a `kernel.exception` subscriber both hand a `Reply` to one `ReplyResponder`. A pure `ErrorTranslator` maps a throwable to a `Reply`.

**Tech Stack:** PHP 8.5, Symfony 8.1 (HttpKernel, Serializer), PHPUnit 11, `zircote/swagger-php` (dev only), `./bin/test`, `./bin/quality`.

**Spec:** Contract `packages/web-app/doc/features/0002-server/error-response.md`. No module spec exists for this slice. The contract left three items to the spec. This plan closes them in "Decisions" below.

## Decisions the contract left open

- **`invalid_json` vs `invalid_body`.** `MapRequestPayload` raises `BadRequestHttpException` in both cases. It differs by `getPrevious()`. A previous of `Symfony\Component\Serializer\Exception\NotEncodableValueException` is `invalid_json`. Any other 400 `HttpExceptionInterface` is `invalid_body`.
- **OpenAPI version and location.** OpenAPI `3.1.0`, YAML, committed at `packages/web-app/doc/openapi.yaml`. Regenerated by `./bin/composer web-app openapi`.
- **Upstream status number.** The library does not expose it. Only the message text of `HttpFetcherException` holds it. Task 1 adds `HttpFetcherException::$statusCode` to `packages/article-reader`. Parsing the message is rejected as brittle.
- **Listener priority.** `TranslateApiException` runs at priority 10. `setResponse` stops propagation, so Symfony's own `ErrorListener` (priority 0) does not run for `/api`.
- **OpenAPI scope.** `POST /api/archives` documents 200, 201, 400, 415, 422, 500, 502. 404 and 405 are route-level answers and have no entry on that operation.

## Global Constraints

- Run PHP tests with `./bin/test web-app` (library: `./bin/test article-reader`). Final gate is `./bin/quality`. PHP tooling runs in Docker only.
- Error body is exactly `{"code": string, "message": string}`. Success body is exactly `{"url","title"}`. No envelope, no `status`, no request id in the body.
- JSON is written with `JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR` in one place only.
- `ArchiveService` catches `OrchestratorException` and nothing broader.
- Only `ArchiveFailureMapper` and `ArticleReaderAdapter` name library error types for translation.
- Statuses: 400 refused request or URL, 422 page cannot be archived, 502 the page's site, 500 Eleanor. 404, 405, 415 from the framework. Per ADR 0001.
- 502 and 500 write the original throwable to the `application` channel at `error`. 400, 404, 405, 415, 422 write no error line.
- No new runtime package. `zircote/swagger-php` is `require-dev`. No runtime schema validation.
- Docs and comments in English. Public classes and methods carry docblocks like the neighbouring classes. Classes that are not services carry `#[Exclude]`.
- Commit scope `web-app` (or `article-reader`), Conventional Commits.

## Message and code table

The translator and its tests use these exact values.

| Status | `code` | `message` |
| ------ | ------ | --------- |
| 400 | `invalid_json` | The request body is not valid JSON. |
| 400 | `invalid_body` | The request body must be a JSON object with a string url. |
| 400 | `url_syntax` | The URL is not valid. |
| 400 | `url_policy` | The URL is not allowed. |
| 400 | `url_rejected` | The URL was refused. |
| 404 | `not_found` | The path does not exist. |
| 405 | `method_not_allowed` | The method is not allowed for this path. |
| 415 | `unsupported_media_type` | The request must be sent as application/json. |
| 422 | `extract_no_content` | The page has no article. |
| 422 | `sanitized_empty` | The article is empty after purification. |
| 422 | `redirect` | The page redirects. Send the final URL. |
| 422 | `content_type` | The page is not HTML. |
| 422 | `body_too_large` | The page is larger than the size limit. |
| 502 | `transport` | The page's site could not be reached. |
| 502 | `upstream_status` | The page's site answered with status {N}. (no number: The page's site answered with an error status.) |
| 500 | `encoding` | The page's character encoding could not be read. |
| 500 | `extract` | The article could not be extracted. |
| 500 | `sanitize` | The article could not be purified. |
| 500 | `unexpected` | Something went wrong on the server. |

## Review Focus

1. A path such as `/apiary` or `/api-docs` is not under `/api`. The listener must leave it alone. Task 6 `test_leaves_a_path_outside_api_untouched` uses `/apiary`.
2. A `application/json` request with an empty body is a broken body. It answers 400 `invalid_json`, not 500. Task 6 route case `empty body`.
3. JSON `null`, `1`, and `"x"` as the whole body answer 400 `invalid_body`. Task 6 route cases `json null`, `json number`, `json string`.
4. A failure's own message must not reach the client. An `ArchiveException` whose cause says `connect to 10.0.0.5 refused` answers 502 `transport` with the fixed sentence. A throwable with message `/etc/secret` answers 500 `unexpected`. Task 4 `test_failure_text_never_reaches_the_body`, Task 6 `test_unexpected_error_answers_the_fixed_sentence`.
5. A programming `Error` thrown by the fetcher must not become an `ArchiveException`. Task 2 `test_an_error_from_the_fetcher_passes_through`.
